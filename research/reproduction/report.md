## Product findings and corrections

**R1: RC1 rejected its own large generated summaries.** All twelve retained oversized exploration summaries reproduce `lab verify` exit 2. RC2's reader explicitly passes a 64 MiB bound into the decoder. `ac.py` and `ac_check.py` archive members are byte-identical RC1→RC2. The review's exploratory scenario generated a >1 MiB summary and verified successfully in RC2 and again in RC3, with exact original raw/evaluation bytes. This repairs the observed size defect; the review does not claim exhaustive 64 MiB boundary testing. RC1 rejection evidence remains part of the study record.

**R2: reserved policy identifiers passed validation but prevented persistence.** On RC2, changing a nonbaseline policy ID to `summary` yielded `VALIDATED_INPUT`, then `lab run` exited 2 with `FileExistsError` while writing the actual summary, leaving a partial bundle. `scenario`, `manifest` and `checksums` likewise share reserved filenames. Input and stdout/stderr are retained in `reserved-summary.json`, `reserved-validate.log`, `reserved-run.log` and `reserved-summary/`. Root's RC3 rejects all four before directory creation. Reviewer checks exercised both validate and run for every name, plus a successful ordinary `custom_control` ID. Three RC3 cross-study reruns produced byte-identical raw/evaluation files, including the large-summary case. AST comparisons show unchanged `example`, `solve` and `produce`; `ac_check.py` is byte-identical. The entire `ac.py` hash appropriately changes because validation changed.

**R3: huge JSON integer escaped structured rejection.** RC3 accepts JSON parsing of a 401-digit integer, then `math.isfinite` in its numeric predicate raises `OverflowError` before checking the bounded numeric range. `lab validate` exits 1 with a traceback instead of exit 2 structured `REJECTED`; a campaign would also bypass the caught input-error path. The exact input and error are retained as `invalid-huge-integer.json`, `.stdout`, `.stderr`. The minimum correction is a range check before float conversion, with validate/run/campaign rejection checks. No valid admitted numeric value needs to change. RC4 now checks the numeric range before `math.isfinite`. The exact malformed input returns structured `REJECTED`, exit 2, with no traceback. Reserved identifiers remain rejected; ordinary benchmark, exploratory and custom-ID inputs remain accepted. All 13 validate/identity/source-comparison checks pass. RC3→RC4 `example`, `solve`, `produce` ASTs and evaluator bytes are unchanged; the saved source diff contains only the numeric predicate ordering. No additional producer scenario was run after the cap. Root separately owns run/campaign and clean-release regression coverage.

CLI exit 0 records a study; it does not certify feasibility or success of every solver trajectory. Verification checks integrity and independently reproduced evaluation, not engineering suitability. Declared infeasibility, invalid-result, failed-solver and cancelled states must remain prominent in release material. Original defaults are intentionally baseline-infeasible and cannot be advertised as a feasible comparison ranking. No additional numerical defect was observed in the tested scope. Broad schema fuzzing, archive abuse testing, all admitted electrical extremes, and an independent browser/human usability study were not performed by this reviewer.
