## Decision procedure

### 1. Build the candidate matrix

For each candidate, record exact evidence or `UNRESOLVED` for:

- publisher/maintainer, canonical URL, exact release/date/revision and retrieval date;
- asset boundaries: technical document, machine-readable model, profiles, corrections, and reference outputs;
- license/terms for each asset, attribution, modification, redistribution, share-alike/database obligations and access restrictions;
- intended analysis, nominal frequency, phases, voltage levels, topology size/types, regulators/taps/capacitors/loads/generation and known special modeling features;
- input units, per-unit bases, line/phase conventions, load/generator and branch-flow signs;
- official reference outputs, solver/method/settings used to produce them, precision and known corrections;
- profile availability, time zone/calendar, interval duration/aggregation, observed versus synthetic status and missingness;
- conversion required for a provider-neutral contract and whether it is lossy;
- evidence gaps, reviewer needs and decision state.

Use decision states `PASS`, `FAIL`, `UNRESOLVED`, and `NOT_APPLICABLE`. Do not turn missing evidence into a low score.

### 2. Apply selection criteria in order

A candidate is selectable only when:

1. the exact technical asset and version are stable enough to cite;
2. use is lawful and the repository/bundle may either redistribute it under recorded obligations or reference an authorized external retrieval without false portability claims;
3. topology, units, signs, base quantities and reference outputs are sufficiently defined to build an adapter conformance case;
4. the case is small enough for an initial local study without distributed compute;
5. it exercises relevant distribution behavior without requiring fast dynamics or protection claims;
6. profiles are available under adequate terms or can be supplied later as clearly synthetic inputs without changing feeder reference claims;
7. known corrections and limitations are recorded.

Rights, missing model meaning, or absent reference outputs are hard gates. Ease of conversion and familiarity are preferences only after the hard gates pass.

### 3. Define the metric contract

For the selected feeder, define each metric with quantity, unit, basis, sign, location, horizon, aggregation and source/decision authority:

- bus voltage magnitude and phase-specific limit exposure;
- branch/transformer current or apparent-power loading using the source/model's rating definition;
- real and reactive nodal/system balance residuals kept separate;
- imported energy, actual generation injection, exported/served energy, dissipative or real dump sinks, stored-state change, and separately available-versus-curtailed generation over explicit intervals;
- storage charge/discharge power, state of charge and round-trip/standing losses when later added;
- transformer tap count/state and thermal exposure only when a validated thermal model exists;
- solver convergence/status, missing output and out-of-domain state;
- runtime/resource metrics labeled as software measurements.

The electrical balance uses actual injection and never subtracts available-but-curtailed energy. The contract includes the tiny `10 kWh available / 4 kWh curtailed / 6 kWh injected / 5 kWh served / 1 kWh lost` control from [ARCHITECTURE.md](../../ARCHITECTURE.md) so a double-counted curtailment implementation will fail review.

Do not assign voltage/loading/numerical/conservation tolerances until each has a cited source, benchmark precision argument, refinement evidence, or named engineering decision. Record unresolved values as blockers and say which downstream acceptance they block. A generic package default is not justification.

### 4. Fix reference and failure controls

The benchmark contract must identify:

- at least one official reference solution field that GH-004 can compare after engine adoption;
- how native sign/unit/per-unit conventions map to the canonical contract;
- one topology/reference failure case (for example a dangling element reference) that must be rejected before a solver call;
- one unit/basis mismatch that must be rejected;
- one deliberately perturbed expected output that the later evaluator must detect;
- evidence that distinguishes source transcription, adapter conversion and solver disagreement.

No numeric tolerance is embedded in a failure control until its justification is accepted.

### 5. Decide or block

Write one outcome:

- `SELECTED_FOR_MAINTAINER_REVIEW`: one candidate satisfies all hard criteria, with unresolved engineering thresholds explicitly gated;
- `HOLD_FOR_RIGHTS_REVIEW`: technical fit exists but terms/redistribution require qualified decision;
- `HOLD_FOR_ENGINEERING_REVIEW`: source/model is clear but required limits cannot be justified;
- `REJECT_AND_INSPECT_NEXT`: record the failed hard criterion and inspect the one bounded alternate;
- `BLOCKED_NO_CREDIBLE_PUBLIC_FEEDER`: preserve evidence and propose an original synthetic fixture only for GH-003 contract development; do not claim GH-001 complete or silently weaken its public-feeder acceptance.

The maintainer makes the final selection and records it in `STATUS.md` after reviewing the packet.

## Stop and escalation conditions

Stop and preserve findings when:

- the candidate's exact rights or redistribution terms are absent or ambiguous;
- the authoritative model/reference outputs cannot be matched to the same version;
- a source requires login, payment, restricted access or external contact not already authorized;
- topology/model meaning depends on undocumented third-party conversion;
- a required limit or tolerance needs qualified judgment that is unavailable;
- completing the task would require installing/running a numerical engine, downloading/bundling data, or changing another task's scientific gate;
- the base revision or owned paths have changed under another writer.

Ask the maintainer for the smallest decision: rights interpretation, benchmark choice, engineering reviewer, or expanded task authority. Continue only evidence gathering that is independent of that decision.
